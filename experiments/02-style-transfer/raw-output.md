## Draft

Mem0 keeps a superseded memory and still returns it in search by default. Keeping it is not the same as treating it as current.

The account is dated August 4, 2026, and updated September 28, 2026. It is a vendor description, not independent proof. Superseding is only for a clear replacement of the same fact. The old memory is marked superseded and pointed at the replacement. If the link is ambiguous, that step should not happen. `latest_only=true` returns the items that have not been superseded. It keeps those memories because history can still be useful, and it separates that history from a current-only view. The write-up does not prove the classifier, does not prove correct selection when both versions are shown, and does not claim this is the only valid design.

OpenAI’s help page on memory controls, June 4, 2026, is also a vendor account, not independent proof. Remembered information changes with context, and the system selects what is relevant. “Dreaming” is a trip memory that should later reflect that the trip already happened, inside an updated summary, rather than only as a static saved-memory list. Correct conflict choice is not shown, and the memory summary may omit details or sources. The full retrieval algorithm is withheld. There is no claim of identical controls on every account; they vary by plan, region, platform, and workspace. A user can flag a memory as incorrect or outdated and, where supported, edit it. Chat-history derivatives can be revised. A saved memory can survive deletion of the source chat. “Don’t mention this again” changes personalization and leaves the source in place. Disabling chat-history reference schedules derived information for deletion while the chats remain. The page does not claim that older material is kept because it is useful.

LongMemEval, submitted October 14, 2024 and revised March 4, 2025, ties an answer to when a statement was true. A knowledge update means recognizing a later revision. Indexing, retrieval, and reading are separate, so retrieved text can still be misread. The drop of roughly 30 percent is an aggregate on sustained interaction, not a knowledge-update score and not a universal fix. The paper does not test the preference-change scenario it names, and it states no retention policy.

Chen, Wang, and Brinton, submitted September 3, 2026, describe distributed agents. A new shared fact can leave a plan from the old fact still running. The executor can see the new requirement while the old plan remains. Fresh state does not guarantee fresh derived behavior. Across 30 controlled workflows with a post-plan revision, a freshness-only executor used the obsolete plan every time. PlanFence finished all 30 with no invalid action. It validates recorded plan dependencies before an external action and can replan or block. The check stays dependency-scoped. The 30 workflows are controlled safety and cost results, not a consumer-chat finding. Extending that check to ordinary chat personalization is a reasonable design inference, not a finding of that paper.

I do not get one meaning of “current” from these four packets. It can mean response-relevant, non-superseded after a clear same-fact replacement, true at the required time, or governing the action. No packet equates it with the newest stored item. No packet shows that the newest preference is current, or that conflict handling in the OpenAI or Mem0 accounts is reliable.

The reasons for keeping an older fact do not line up either: search, a separate source lifecycle, a time-specific question, or a dependency to validate. The dependency case is not the same as presenting the old record as the current preference. The packets do not show that every old preference should be kept, or that keeping it authorizes continued use.

Supersede only for a clear replacement of the same fact, and skip that when the link is unclear. That is Mem0’s rule; correct application is not established. Retrieval is not correct use. A retrieved passage can be misread, both versions may be returned, and a fresh fact need not refresh an earlier plan. Carrying time and update structure into retrieval and reading is a reasonable design inference from LongMemEval. Joining user correction, conservative replacement, update-and-time tests, and a dependency check into one pipeline is an inference.

No packet measures when a new preference replaces an old one rather than adding another current fact, beyond Mem0’s ambiguity rule. A rewritten summary, current-only search, the newest item, or a dependency check is not shown to be enough on its own. A general rule for a changed preference is still open.
